# App Store Product

制作让用户一眼看懂产品价值、与真实 App 一致、技术规格可提交且素材来源可追溯的商店产品素材。

## 先判定交付类型

不要看到“App Store 宣传图”就直接排版。先结合用户原话、App Store Connect 截图或上下文，明确属于哪一类：

- **普通截图 / App 预览和截屏**：1–10 张，以真实 App 使用体验为主体；可加版式和短文案。
- **自定产品页（CPP）**：面向特定受众或投放场景的另一套普通截图、预览和推广文本；不是一种新的图片尺寸。
- **标题和搜索结果 / Creative Assets**：产品页标题图、搜索结果图或通用素材；是独立于普通截图的可选创意版位，可以超出完整界面截图的表达方式。
- **App Preview 视频**：如果用户要视频，先核对视频规格；本 Skill 的自动脚本只验静态图。

如果术语仍有歧义，先查看用户给出的 App Store Connect 页面。只有会明显改变交付物时才提一个简短问题。详细分流见 [references/deliverable-modes.md](references/deliverable-modes.md)。

## 强制原则

1. **制作前核对 Apple 官方文档。** 规格会变化。打开当前的 Screenshot Specifications、Creative Assets Specifications、Asset Best Practices，并在交付说明中记录核对日期。`references/current-specs.md` 只是已验证基线，不得替代实时核对。
2. **App 名称、功能和界面必须真实。** 优先从项目配置、真实构建和用户提供的信息中确认，不能用仓库名、模块名或占位名代替公开产品名。
3. **先做内容策划，再截图。** 空白新用户界面、Lorem ipsum、机械重复卡片和临时数据不能作为定稿。需要时先在隔离的演示数据或测试夹具中准备有叙事、有层次、符合产品用户画像的内容。
4. **普通截图展示真实使用体验。** 不得用纯口号海报替代整个 App 画面。创意素材则应聚焦品牌或核心价值，但仍须与实际功能相关。
5. **营销素材默认放在项目目录之外。** 除非用户明确要求，不把成品、源图、字体、临时截屏或压缩包加入代码仓库。临时采集代码也优先放隔离目录，不污染生产 target。
6. **不推断上传或发布权限。** “制作”“定稿”只授权生成文件；只有用户明确要求时才登录 App Store Connect、上传、提交审核或发布。
7. **可商用是可追溯，不是口头保证。** 对每个图像、字体、图标、UI 和文案记录来源与许可；生成式素材记录工具、日期和提示词。不得承诺 Apple 一定通过，也不得承诺生成素材具有排他版权。

## 工作流

### 1. 建立素材简报

从 App 和用户目标中整理：公开 App 名称、目标用户、核心价值、必须展示的功能、支持设备、语言、品牌色、现有 UI、希望避免的表达、交付类型和输出目录。信息足够时直接推进，不反复确认。

为截图组先写“故事顺序”：首 1–3 张承担搜索结果和第一屏转化，后续再展开完整功能。每张只表达一个主要利益点，整组覆盖一条真实使用路径，而不是功能清单堆砌。

### 2. 准备真实而精心的内容

- 使用能被目标用户相信的标题、正文、图片、日期、标签、头像或状态。
- 内容之间要有节奏：概览、具体内容、创作过程、完成结果、变体或模板。
- 不为了截图修改真实用户数据。优先使用测试、演示或首启示例内容；若用户明确要求把内容预埋进产品，再作为独立代码改动处理，并遵守仓库规范。
- 若使用生成图片，只生成产品语境需要的素材，避免可识别品牌、人物肖像风险、文字水印和模仿特定在世艺术家。

普通截图的详细制作方法见 [references/screenshot-production.md](references/screenshot-production.md)。标题与搜索结果素材见 [references/creative-assets.md](references/creative-assets.md)。

### 3. 捕获和设计

- 从真实构建捕获最新版 UI；状态栏时间、电量、语言和内容状态要一致。
- iPhone 与 iPad 应按各自布局重新构图，不要把手机图机械放大到平板画布。
- 可用 HTML/CSS、矢量工具或图像编辑器排版；保留可编辑源文件并固定字体版本。
- 标题简短、收益明确、缩略图可读。不要让应用名、主功能或画面焦点被裁掉。
- 系列保持统一色彩、字体、留白、阴影、设备角度和文案语气；允许每张内容变化，但不能像不同品牌拼在一起。

### 4. 逐级审查

至少检查四个视图：原尺寸、整组总览、约 600px 宽缩略图、Apple 安全区/中心裁切。创意素材还必须在 App Store Connect 的 Preview 中检查不同设备、方向和语言。

逐项确认：

- 产品名、文案、标点、简繁体和数字没有错误；没有仓库名或旧名称。
- 功能与当前版本一致，没有虚构奖项、价格、折扣、网址、其他平台标志或不可验证承诺。
- 主标题和焦点在缩略图仍清楚，首屏不是大片无意义空白。
- 截图中的 UI、内容与装饰形成整体，而不是互不相关的三栏或边角照片。
- 关键元素位于官方模板安全区；出血部分即使裁切也不破坏语义。
- 所有上传图尺寸正确、RGB、无 alpha；上传目录里没有说明图、红框图、缩略图或 `.DS_Store`。

### 5. 自动验收与交付

运行：

```bash
python3 scripts/validate_assets.py --mode <模式> <上传图片...>
```

也可以直接传只包含同一版位成品的目录。模式包括 `creative-header`、`creative-search`、`creative-universal`、`iphone-required`、`ipad-required`；官方规格刚变化时可用 `--expect 宽x高` 按实时规格覆盖基线。若有结构化安全区清单，再运行：

```bash
python3 scripts/validate_safe_area.py layout-manifest.json
```

建议交付结构：

```text
交付根目录/
├── upload/       只放可直接上传的最终文件
├── review-only/  总览、缩略图、安全区检查图
├── source/       可编辑源文件、字体、原图、生成记录
├── 上传说明.md
└── 素材来源与许可说明.md
```

需要打包时，另给一个“可上传包”和一个“可编辑源文件与许可包”，并校验压缩包可解压。交付说明应写明版位映射、尺寸、语言、官方规格核对日期、验收结果，以及“未代替用户上传/发布”的事实。许可和打包细则见 [references/commercial-and-delivery.md](references/commercial-and-delivery.md)。

## 完成标准

只有在以下条件同时满足时才称为“可上线定稿”：设计完成且经过缩略图审查；真实内容和功能核对通过；尺寸、色彩模式、透明通道与文件数验证通过；来源和字体许可可追溯；上传包不混入审查或源文件；未把营销素材误放进项目。若任何一项尚未验证，应明确称为草稿或待核验版本。
