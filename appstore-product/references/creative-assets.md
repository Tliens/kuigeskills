# 标题与搜索结果创意素材

## 共同策略

- 两个版位应像同一品牌，但不必使用同一构图。
- 使用真实 UI、真实产出或与产品相关的原创/已授权视觉；装饰不能比产品更抢戏。
- 文案是视觉的补充，不是说明书。优先一个主句和一个极短补充。
- 从 600px 宽缩略图判断，而不是只在 4K 画布上判断。
- 将主文案、品牌和不可裁切焦点放进官方安全区；背景纹理、光影、部分设备或作品可以出血。

## Product Page Header

目标是设定品牌气质和核心价值。只表达一个清晰概念：

- 让首次访问者快速感到“这是怎样的产品”。
- 不要堆放三个等权界面、功能列表、徽章和大量小字。
- 可以只展示一个有辨识度的成果、人物动作或 UI 局部，但应与 App 后续截图形成连续叙事。
- 宽幅画布容易制造无意义空白；留白必须服务于主标题、节奏或 App Store 裁切。

## Search Results

目标是让带着明确搜索意图的人立即理解用途：

- 一眼回答“这个 App 做什么”。
- 优先展示实际界面、内容、创作过程或最终结果。
- 文字和焦点在小卡片中仍需辨认；不要依赖细小 UI 文本解释产品。
- 如果同时展示编辑过程和成品，应让二者形成明确因果，而不是孤立的三栏陈列。

## 通用素材

只有当同一构图在 Header 和 Search 两种裁切下都成立时，才使用 16:9 Universal。不要为了少做一张图而把所有内容缩到中央。分别设计通常能获得更强的版位表现；是否使用通用素材由品牌一致性、制作成本和裁切鲁棒性共同决定。

## 安全区工作方法

1. 下载 Apple 当前模板并记录版本/日期。
2. 在源文件中建立画布、安全区、关键元素矩形和预期出血。
3. 导出无安全区线的成品，同时输出带红框的 review-only 图。
4. 生成中心裁切预览和 600px 缩略图。
5. 用 `validate_safe_area.py` 校验结构化矩形，再在 App Store Connect Preview 检查真实呈现。

安全区脚本只证明“声明的矩形在范围内”，不能判断设计是否精致，也不能代替 App Store Connect 的设备预览。

## 常见失败

- 把 App 名称/副标题/关键词误认为“标题和搜索结果”素材。
- 把 CPP 普通截图当成独立 Creative Assets。
- 完整手机缩得很小，四周用无关图库照片填满。
- 让每个对象占一列，缺少视线流动和前后关系。
- 大面积空白 App 页面、占位数据或默认头像暴露“未准备内容”。
- 主标题或 App 名在中心裁切后消失。
- 安全区被误解为所有素材都必须缩进，导致画面小而松散。
